# 日英併記のプロフィール設定 (#12)

2026-10-13。#11の暗号化保管層に接続する設定・編集タブ。UXの正本は [AUTOFILL-UX-SPEC.md](AUTOFILL-UX-SPEC.md)、暗号/失効/保存障害の契約は [ENCRYPTED-PROFILE-STORAGE.md](ENCRYPTED-PROFILE-STORAGE.md)。実プロフィール・旧DMG・実Amexフォームにはアクセスしない。

## 操作

ビルドした拡張を読み込み、拡張アイコンのコンテキストメニューから「オプション」、または拡張管理の「拡張機能のオプション」を開く。`options_ui.open_in_tab`で専用の`settings.html`を表示する。

1. 初回は**事業情報 / 個人情報 / カード設定 / セキュリティ**の4区分へ入力する。申込時に必要/任意・形式の説明、DBAなし、個人事業主、住所同一の条件分岐に従う。
2. セキュリティで12文字以上のマスターパスワードと確認入力を設定し、「暗号化して保存」。未入力・形式未完成でも途中保存できる。保存後はロックされ、画面の値は消去される。「このタブを閉じて構いません」と表示されたら閉じてよい。
3. 次回はパスワードで解除して編集する。解除が残っている場合も「編集を開く」を明示クリックするまでプロフィールを表示しない。編集の保存後もロックされる。
4. 解除中にパスワードを変更できる。プロフィールに未保存の変更がある間は先に保存する。変更後は新しいパスワードで解除する。
5. パスワードを忘れた場合は復旧できない。セキュリティの「登録情報を削除」で、不可逆であることのチェックと最終ボタンによる確認後に初期化する。キャンセル/ESCでは何も削除しない。破損/未知versionの場合も同じ確認が必要。

設定タブは申込フォームを検出・入力・送信しない。通常Popupとの連携は[Popup・自動入力](POPUP-AUTOFILL.md)を参照。従来の保存情報の読取・自動変換・削除は行わない。

## ラベルと入力

36項目の出典対応表は [Issue #10ラベル照合](ISSUE-10-FOLLOWUP.md#ラベルの照合) を維持する。過去の表示記録がある30項目も、現在の実サイトでの入力成功を意味しない。

- 当初未確認だった6項目は、2026-10-13の追加読取と実入力確認で、Card design / materialの固定選択肢ラベル、自宅および事業City / Stateのid・ラベル・形式を照合したため項目の未確認表示を解除した。選択肢一覧は全条件下で照合できていないため未確認表示を維持する。ラベル照合は全項目の実入力成功を意味しない。
- データkeyと英語保存値は既存定義を維持し、ラベル/選択肢の日本語説明を分離する。州・準州・軍用等も英語略号を保存し、日本語は説明にだけ使う。`yes/no`はcheckboxの内部値で、Amex上の選択肢とは表示しない。
- UI専用の説明は`src/settings/fields.ts`。既存の36項目/選択肢/条件validationは`src/full-profile.ts`。保存時は構造（許可項目・型・長さ・制御文字・選択肢）だけを検査する。email等の形式・相互条件の検査は自動入力時に行い、未完成の値をWorkerで除外してからページへ渡す。エラー表示は固定の項目名と原因のみ。値・生のZodエラーをエラー一覧へコピーしない。
- 生年月日は通常のテキスト表示。SSN・Federal Tax IDは既定でマスクし、個別の表示切替が可能。パスワードも表示切替付き。機密値をDOMのHTML属性やテキストラベルへコピーしない。
- 条件付きで不要になった項目は編集中は保持し、条件を戻せば再表示できる。保存用データでは空欄にし、住所同一を理由に自宅住所へ値を捏造コピーしない。
- 従業員数の申込時条件は1〜999。範囲外も途中保存はできるが、自動入力前に除外する。保存値を推定して修正しない。
- パスワードは12 Unicode code points以上、最大1024 UTF-16 code units。文字種の強制・trim・Unicode正規化なし。確認入力の一致を必須とし、送信開始時に入力欄を空にする。

## 編集中の平文と状態

**背景タブでは編集中データを画面メモリに保持し、戻った際にWorkerへ解除状態を再照会する方針を2026-10-13にユーザー承認済み。**

- 値の保持先は設定documentの入力要素だけ。プロフィールの別キャッシュ、local/session保存、localStorage、IndexedDB、ログ、外部送信なし。明示操作時のmessageには必要なプロフィールを含む。
- タブが非表示になると編集フォームを隠し、表示切替をマスクへ戻し、パスワード欄を消す。戻った際にrevision/epochと解除状態が同じなら編集中データを再表示する。状態照会が終わるまで古い値を表示しない。
- 別の設定タブ等のロック/更新/削除は`storage.onChanged`で検知し、Workerの状態を再照会。失効・競合なら未保存の値も消す。UIだけで解除済み状態を復元しない。
- 処理中は入力・選択を無効化する。条件付き項目も `busy || 条件により非表示` で無効化し、処理後は条件に該当する項目だけ無効のままにする。
- 手動ロック、保存、PW変更、初期化では送信前に画面からプロフィールを消す。pagehideでも消去し、BFCache復帰は再照会から始める。未保存の変更があるページを閉じる/再読込する際はブラウザの確認を求める。
- `readForEditing(revision,epoch)`は、完全一致の正規設定タブへの専用応答のみ。popup/content script/query付きURL等へ平文を返さない。復号中のlock受付とrevision/epoch変更を再検査し、設定document側も応答の受信後に再照会してから値を表示する。
- 編集読込は一回限りAutofillの使用開始ではないため、保持OFFでも読込時にsessionを消費しない。保存/PW変更/手動lockでは失効する。OFFで設定タブを閉じた場合のlock送信はbest effortであり、document終了時の通信完了を保証しない。実Autofill開始時の一回消費は#11の契約を維持し、#13で統合する。
- Workerの直列キューは完了した平文応答を保持しない。JS文字列、Chromeのmessageコピー、GC、OS swap等の完全なゼロ化は保証しない。

## エラーと初期化

- 誤PWは固定メッセージで再入力を案内。未知version/破損を空プロフィールとして扱わず、「登録情報を開けません」と再確認/初期化導線を表示する。
- `COMMIT_UNKNOWN`や応答切断は「結果を確認できません」と表示し、成功・未保存を断定しない。勝手な再送/rollback/初期化はしない。現存状態を再確認し、PW変更後は新PW、失敗するなら旧PWで確認する。
- `STORAGE_WRITE`では表示中データを消して操作を止め、「拡張を再読み込み」導線を出す。epoch更新とsession削除が同時に失敗した場合に、Worker再起動だけでは失効を保証できない#11の制約に従う。
- 初期化はこの設定画面で登録した暗号文と解除状態のみ。他機能、旧7項目、DMGには触れない。非秘密の失効UUIDは残る。

## 合成データでの検証

```sh
npm run check
PROBE_TEST_BROWSER=chromium npm run test:settings
PROBE_TEST_BROWSER=brave SETTINGS_HEADED=1 npm run test:settings
```

`test:settings`は**配布用の実Worker/設定HTML/CSS/JS**を一時browser profileに読み込む。固定の合成marker・無効なゼロ識別子のみを入力。外部リソースを遮断し、既存ユーザープロファイルは開かない。終了時に一時profileを削除する。CIではスクリーンショット/trace/HARを保存しない。ローカルで`SETTINGS_SCREENSHOTS=/private/tmp/...`を明示した場合のみ合成画面を保存する。

Playwrightの通常接続はfocus emulationにより全タブをvisibleとして扱うことがある。`tests/settings-browser.ts`は所有する一時browserへ`connectOverCDP({noDefaults:true})`で接続し、実際のタブ非表示/表示イベントを検証する。通常の可視状態を上書きしない。

検証対象: 36項目の日英ラベル、未確認表示、条件分岐、形式/PW確認、マスク、暗号化保存→同profileブラウザ再起動→解除→編集、背景draft保持と再マスク、別タブlock、PW変更、初期化確認/キャンセル、未知/破損データからの復旧、保存結果不明/Storage故障表示、local/sync/ログ/ネットワークへの平文不在。

このテストは本番Amex入力、本人の旧DMG移行、配布更新、電源断、全OSの動作保証ではない。それらは#13/#16で扱う。

2026-10-13の結果: `npm run check`は74 tests・lint/typecheck/format成功。実Chromium headlessの一連フローと、Brave headedの追加競合/幅600px表示検証が成功。独立レビューで破損データの復旧導線と州選択肢の説明を修正し、再レビューで残るblocking findingsなし。レビュアーも74 testsを独立実行した。

追加回帰検証: create/update/unlock/changePasswordの実リクエスト送信を一時停止し、可視入力・選択欄と全プロフィール欄の無効化を確認する。解除欄はfocus/キーボードでも変更できないこと、完了後とDBA・事業形態・住所同一の切替後は条件に応じたdisabledへ戻ることを検証する。保存・PW変更時にプロフィール画面を隠す既存仕様も維持する。

## Chrome標準パスワード管理

Chromeは`chrome-extension:`ページをパスワード管理の対象から除外している。`autocomplete="new-password"`/`current-password`の指定だけでは、設定タブやPopupのマスターパスワードを標準の保存・自動入力へ対応させられない。[Chromium実装のCanShowBubbleOnURLとIsPasswordManagementEnabledForCurrentPage](https://github.com/chromium/chromium/blob/main/chrome/browser/password_manager/chrome_password_manager_client.cc)を2026-10-13に確認した。別方式は未実装であり、パスワードを拡張の平文ストレージに保存しない。
