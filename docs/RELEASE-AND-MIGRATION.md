# 実機検証・配布準備・旧方式の扱い (#16)

対象は個人利用のunpacked拡張。通常操作は[Popup](POPUP-AUTOFILL.md)と[設定タブ](PROFILE-SETTINGS.md)で完結する。Web Store公開・署名CRX・自動更新サーバーは用意していない。本書の「更新」は**同じ配置場所・同じ拡張IDでunpacked拡張を再読込する手動更新**を意味する。

## 通常版と合成版

| 用途               | コマンド                                             | 出力・制約                                                                               |
| ------------------ | ---------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 通常利用           | `npm run build:extension`                            | `dist/extension`。Amex host権限。pathはコードで制限。loopback不可                        |
| 配布物監査         | `npm run test:package`                               | 8ファイル、権限/CSP、依存元、旧経路・既知合成値の非混入、古い余剰ファイル拒否を検査      |
| 合成Popup E2E      | `PROBE_TEST_BROWSER=chromium npm run test:extension` | `dist/extension-fixture`。loopback権限のみ、実Amex権限なし                               |
| 製品ライフサイクル | `PROBE_TEST_BROWSER=chromium npm run test:release`   | 新しい一時profileと合成拡張コピー。headedで複数windowのfocusを検査（Linux CIはxvfb-run） |
| 通常Chrome実機     | `PROBE_TEST_BROWSER=chrome npm run test:release`     | 最初の一度だけ開いた専用ChromeでUI読込。再起動時は再インストールしない                   |

合成拡張の名称は **Amex Autofill — Synthetic test only**。表示された一時ディレクトリを「デベロッパーモード」→「パッケージ化されていない拡張機能を読み込む」で選択する。普段のprofile・既存拡張・実保管庫を使わない。10分の読込待ちを過ぎた場合はテストをやり直す。終了時に削除するのは、このテスト自身が作った一時ディレクトリだけ。

ビルドは固定の生成ディレクトリをレビュー対象ファイルだけで作り直す。`dist`へ個人情報や手作業のファイルを置かない。合成ビルドは通常版を上書きしない。バンドルの入力一覧は`dist/extension-inputs.json`へ出し、拡張には同梱しない。監査は権限・依存元・既知の禁止文字列を検査するもので、任意の秘密の不在や外部通信の完全不在を数学的に証明するものではない。

Chromeのhost permissionsはpathを制限しないため、許可対象pathはWorkerと入力関数が毎回照合する。[Chrome公式のmatch pattern仕様](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns)を参照。

## 合成E2Eの範囲

- 設定UIで36項目とパスワードを登録し、暗号化保存。製品schemaから独立した36項目の期待表で、DOMのID/name/type/label、値、整形後の電話/SSN、select/radio/checkbox状態、項目ごとの結果を照合。別々の合成値で氏名の入れ替わりを検出する負例も実施。解除中にブラウザを終了し、同じ一時profileの再起動で登録保持・ロックを確認。
- 誤PW、保持ON既定、解除のみでは未入力、本人操作相当の明示入力、結果の入力済み/一致済み、再実行、手動ロック、保持OFF後のロック。
- 複数window間の古い開始要求を拒否。実行中のfocus変更で以後の入力を停止し、別windowの空欄と結果を保護。
- コピーした合成拡張のversionだけを上げ、通常Chromeでは再読込、コマンドライン読込のChromiumではブラウザ再起動で更新する。拡張ID・暗号文を保持し、解除sessionは失効。再解除後の入力も確認。Chromiumの結果で通常Chromeの再読込成功を代用しない。
- 旧7項目schemaのparseに成功する完全な合成`autofillProfileV1`が未登録画面へ取り込まれず、新規登録・再起動・更新・初期化で変更されないことを確認。
- 初期化の確認、キャンセル時の暗号文保持、新保管庫のみの初期化、sync空、秘密のログ出力なし、フォームsubmit回数0。

既存の`test:extension`はWorker停止/Popup閉鎖・再表示、文書遷移、既存値・一部失敗・最終結果保存障害を扱う。`test:settings`はPW変更、設定保存エラー、破損/未知version、確認付き初期化を扱う。`test:autofill`はDOM・住所候補の直前変更を扱う。ChromeネイティブPopupは`PROBE_TEST_BROWSER=chrome npm run test:extension`で別途確認する。

テストはブラウザ内でloopbackフォームを返し、ページの外部リクエストを拒否する。ブラウザ自身の更新・内部サービス通信を含むネットワーク全体の監査ではない。実サイト・実PII・既存DMGへのアクセスは行わない。trace/HARや実データのスクリーンショットは作らない。

## 旧資産の保全と移行案（本人承認前は実施しない）

推奨する最小移行は**本人が正しい情報を新設定画面へ再登録すること**。旧DMGやYAMLの自動読込、Native Messaging、平文インポート機能は追加しない。誤った古い値を引き継ぐリスクもあるため、本人が項目を確認する。

| 旧7項目の`autofillProfileV1`                         | 通常UIから参照しない。自動移行も削除もしない   | 拡張IDごとの保管先を本人が確認。新方式の初期化では消えない |
| `src/profile.ts` / `src/autofill.ts`と旧fixture/test | 開発用の旧契約として保持、通常バンドルから排除 | 削除は旧資産保全の確認後に別差分で扱う                     |

**新方式が書き込むプロフィールは暗号文のみだが、既存の平文キーや旧ファイルを遡って暗号化する機能ではない。** 旧拡張のアンインストールや保存先変更はデータを失う可能性があるため、確認前に行わない。旧データをCodexへ送る、Git/Issue/PRへ貼る、平文のバックアップを新しく作ることも不要。

承認時には値を送らず、次だけ確認する。

1. 本人が既存データを手元で参照・保全できるか。現行拡張ID/配置場所と別の新拡張を使うか、同じIDを更新するか。
2. 本人が新設定へ再登録し、暗号化保存→ロック→解除→編集で内容を手元だけで確認することへの承認。
3. 旧資産の削除は別途、**削除する対象、保全済みであること、代替手順の動作確認**を列挙して承認。移行の承認を削除の承認として扱わない。

## 本人による実Amex確認（別の事前承認が必要）

準備対象は通常版`dist/extension`とBusiness Platinumの対応フォーム。実Amexへの値入力はこの合成PRの検証に含めない。進める前に、本人の手元で正しいプロフィールを登録し、本人が対応ページを開いて入力を判断する範囲を確認する。実PII、PW、個別URLをチャットへ送らない。

1. 本人が新設定の登録情報を手元で確認。新しい情報が必要なら本人が入力する。
2. 対応ページでPopupの検出状態を確認。対象外/不明なら中止し、無理に入力を有効化しない。
3. 解除し、入力が始まっていないことを確認。本人が「自動入力」を押す。サイト自身のinput/changeによる通信はあり得る。
4. 本人がフォームと結果を照合。不一致・未知ラベル・住所候補は要確認のまま止める。自動送信・契約同意・Accept Card・CAPTCHAを操作しない。
5. Popupを閉じて再表示し、同じ文書の結果を確認。最後に手動ロック。記録は既知フィールドIDと固定状態だけ。

チャットへの報告例は `email: matched`、`businessAddressLine1: address-review` のような固定項目/状態と「送信操作なし」だけ。値、姓氏名、SSN、住所、query付きURL、フォームの画面写真、DOM/Network全文は共有しない。記録から内容を推測して値を補完しない。

## 失敗時の復旧と保証限界

`COMMIT_UNKNOWN`（保存結果不明）では、保存失敗と決めつけて初期化・再登録・旧データ削除をしない。拡張を再読込し、本人が解除して実際に残った内容を確認する。PW変更中なら変更前/変更後どちらが有効かも未確定なので、本人が手元で確認し、どちらでも開けなければ削除せず調査を止める。[保管層の障害契約](ENCRYPTED-PROFILE-STORAGE.md)と[設定の復旧導線](PROFILE-SETTINGS.md)を参照。

ロック清掃失敗は「ロック完了」と見なさず、UIの拡張再読込案内に従う。再読込後も登録情報を開けない場合は、本人の確認付き初期化だけが破棄経路になる。初期化で旧DMG/旧キーは消えない。

Worker停止、拡張再読込、ブラウザプロセス終了は別の事象。全window閉鎖や背景実行ON/OFFの全組合せ、他OS/Chrome版、低速端末の時間/ピークメモリ、Web Store/CRX更新、突然の電源断/媒体障害は、ここで成功した合成試験から保証しない。解除時間は当該端末の参考値だけを出す。確実に解除を終える通常操作は手動ロック。これらの限界は保持チェック下の注意文と矛盾させない。
